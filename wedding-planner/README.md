새 시작 화면은 오늘 할 일·공동 기록·준비 가이드로 구성했습니다. 기존 계산기와 기기별 메모는 [guide.html](guide.html)에 보존했습니다.

**현재 상태:** Firebase 독립 프로젝트·서울 Firestore·회원 제한 규칙은 생성/게시했으며 익명 조회 403을 확인했습니다. Google 로그인은 지원 이메일 등록 승인 대기, 두 회원 등록과 인증된 공동 저장 시험은 미완료입니다. Notion 서버 연동은 코드 준비 단계로 미배포입니다. 새 화면의 공동 저장 버튼은 검증 전까지 비활성화되어 있습니다.

자세한 실제 설정·남은 절차·검증 범위는 [DEPLOYMENT.md](DEPLOYMENT.md)를 확인하세요.

## 운영 구조

| 영역 | 플랫폼 | 저장 |
|---|---|---|
| 행사 정보 · 호텔 문의문 | GitHub Pages | 공개 정적 파일 |
| 예산 시뮬레이션 · 개인 체크리스트 | GitHub Pages 브라우저 | 로컬 스토리지, 해당 기기만 |
| 둘이 공유하는 상담 · 견적 · 의사결정 기록 | 노션 데이터베이스 | 노션 클라우드, 초대된 편집자 간 공유 |
| 주택 및 혼인신고 민감 자료 | 비공개 노션 | 공개 GitHub 업로드 금지 |

**중요:** 현재 웹앱은 Notion API를 자동으로 호출하지 않으며, 기기별 메모는 노션이나 다른 기기로 자동 전송되지 않습니다. 노션 링크 및 페이지 내 웹앱 임베드와 공동 DB 워크플로가 연결된 상태입니다.

## 사용 방법

1. 부부는 동일한 GitHub Pages 주소에 접속해 행사 정보와 계산기를 사용합니다.
2. 둘이 함께 계속 수정할 사항은 **노션 공동 기록 DB**에 새 행을 추가합니다. 분야, 상태, 확인한 내용, 다음 행동을 남깁니다.
3. 기기별 체크리스트나 예산 값을 보관하려면 웹앱의 **JSON 백업**을 사용합니다.
4. 노션 공유는 **이메일로 초대 → 편집 권한**을 사용합니다. 민감한 페이지의 `웹에 게시`는 사용하지 않습니다.

## 실제 실시간 양방향 동기화에 필요한 추가 구성

GitHub Pages는 정적 호스팅이므로 각 브라우저의 저장 상태를 중앙에서 관리하지 못합니다. 나중에 HTML 입력 → 온라인 DB 저장 → 노션 자동 반영까지 구현하려면 인증 가능한 백엔드(Firebase Auth/Firestore 또는 별도 서버리스 함수), 서버에 보관하는 Notion integration secret, 사용자 접근 제어·저장 규칙이 필요합니다. **토큰을 HTML/공개 GitHub에 넣지 마세요.**

연동 준비 점검표:

- [ ] 두 사람의 로그인 방식 확정 (이메일 인증 권장)
- [ ] 클라우드 DB 생성 및 두 명만 쓰기 권한
- [ ] Notion API integration 연결 권한 부여
- [ ] 서버리스 함수에 Notion token을 비밀 환경변수로 등록
- [ ] DB → Notion 기록 매핑과 중복 방지 검증
- [ ] 두 기기에서 저장·불러오기·충돌 테스트
- [ ] 개인정보 공개 여부 재점검
