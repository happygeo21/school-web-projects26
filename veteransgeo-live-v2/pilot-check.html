C. 기존 교사 7명 인수

기존 계정 목록 7/7 일치 · V2에서 기존 기록 읽기 1명 확인 · 나머지 6명 미확인. 신규 운영 V2 승인권과 담당 학교 범위는 아직 활성화하지 않았습니다. 교사 순번과 S1~S7을 임의로 연결하지 않습니다.

  1. 비공개 기존 명단에서 본인 계정과 원래 로그인 방식을 대조합니다. 계정 생성·비밀번호 변경은 하지 않습니다.
  2. 교사 화면의 ‘기존 기록 · 읽기 전용’에서 기존 이메일 방식으로 한 번만 연결합니다. Google 전용이면 이 연결 검사는 보류합니다. 제한 오류가 나면 재시도하지 않습니다.
  3. 학교 코드·확인일·건수 또는 오류 코드·비공개 근거 경로만 담당자에게 제출합니다. 비밀번호·UID·학생 원문은 보내지 않습니다.
  4. 각 교사의 담당 학교 범위를 학교가 명시적으로 승인합니다. 시범학교 담당 교사만 신규 V2 승인·반려·철회 권한을 사용합니다.
  5. 별도 배포 승인 후, 가상 작품으로 자기 학교 관리 허용·타 학교 조회/승인 거부를 확인한 뒤 사용을 시작합니다.

7명 각각의 비공개 인수표: 기존 명단 참조 / 학교 범위 / 로그인 방식 / 읽기 확인일·결과 / 신규 승인권 검사 / 근거 파일 경로. 미확인 학교는 사용 개시 보류, 전체 관리자 추가 0명.

D. 1개 학교 시범 개방 실행 계획

학교·담당 교사·일정 미선정 · 학교 승인 미확인 · 운영 설정 미적용

  1. 시범학교 1개와 담당 교사의 학교 범위를 비공개로 확정하고 개인정보 검토서 승인을 받습니다. 기존 V1은 유지합니다.
  2. 서버 검토본의 시범학교 제한·담당 교사 범위·새 제출 중단 기본값·무료 한도를 확인합니다. 학교 선택만으로 재학생 신원이 증명되지는 않습니다.
  3. 별도 최종 승인 후에만 V2 운영 구성과 서버를 적용합니다. 새 익명 Firebase 계정 생성 여부도 승인 대상입니다. 가상 파일로 운영 연결·승인·철회 검사가 실패하면 학생에게 개방하지 않습니다.
  4. 실물 기기 인수를 마친 한 학교·한 수업 시간에만 시작합니다. 권장 출발 규모는 5모둠 × 사진 1개(1MiB) + 영상 1개(3MiB) = 10파일·20MiB입니다. 개인별 2파일을 받는 30명 수업(60파일)은 현재 한도로 불가합니다.
  5. 공개 피드 전체 재생 30회는 약 600MiB로 월 추정 전송 한도 500MB를 넘습니다. 시범 중에는 교사 화면으로 함께 보고 개인 반복 재생을 줄입니다. 이 수치는 예상치이며 실제 플랫폼 사용량을 함께 확인합니다.

중단: 관리자가 V2 전용 중단 스위치를 꺼 새 제출을 막고 안내합니다. 진행 중인 전송은 완료될 수 있으므로 새 파일 증가가 멈췄는지 확인합니다. 교사 철회·읽기는 유지합니다. 파일·기존 V1 자료를 자동 삭제하지 않습니다.

재개: 원인·학교 범위·공간·직전 24시간 건수·월 전송 여유와 승인 근거를 확인한 뒤 담당자가 재개를 승인합니다. 한도 초기화·계정 재생성·파일 무단 삭제로 우회하지 않습니다. 요청 폭주가 지속되면 개방을 보류합니다.

주의: 익명 계정을 다시 만들면 UID별 제한을 우회할 수 있습니다. 프로젝트 전체 한도는 비용 방어이며 재학생 인증이나 서비스 가용성 보장은 아닙니다. 외부 제출 위험을 학교가 수용하지 않으면 익명 자유 업로드 개방은 불가합니다.

64MiB·20파일은 앱의 보수적 한도입니다. Supabase Free의 제공량 자체와 다릅니다. 공식 무료 요금제 · 이번 작업에서 한도 확대·유료 전환·운영 스위치 변경 없음.
기존 성공 검증은 재사용합니다. 이 화면 확인·결과 다운로드는 배포 승인이나 학교 승인을 대신하지 않습니다.
