# PR #7: 시간 제한 업로드 링크 검토

기준 HEAD: `e500b7e51763dc38fac9119974ef58874a3ac744`. 기존 학생 3단계, 학생·교사·공개 3페이지와 최근 문구/접기/학교 단일 선택을 재사용한다. 이 변경은 Draft 검토용이다. 운영 적용 승인이 아니다.

## 구현과 권한

- 승인된 교사만 기존 교사 페이지에서 학교·15/30/60분을 선택해 링크 발급, 발급 내역 조회, 즉시 폐기 가능. 학교마다 서로 다른 난수 링크이며 학교를 바꿔 재사용할 수 없다.
- 학생은 링크로 접속하면 Firebase 익명 연결을 서버에서 확인한다. 별도 업로드 인증코드 입력란이 없다. 기존 `activityCode`는 그대로 유지한다.
- 256비트 난수 초대 토큰은 URL **fragment**에만 담는다. 학생 페이지는 외부 리소스보다 먼저 읽어 `history.replaceState`로 제거한다. fragment는 HTTP 요청/Referer에 전송되지 않는다. 토큰과 UID에 연결된 일시 권한은 페이지 메모리에만 유지하고, 서버에는 SHA256 해시만 보관한다. 새로고침/다른 탭에는 권한을 복원하지 않는다.
- 새 링크는 파일 업로드 영역의 「새 업로드 링크로 다시 연결하기」에 전체 링크를 붙여 같은 화면에서 연결할 수 있다. 입력값은 즉시 지운다. 인증 실패 때 폼/선택 File/준비된 이미지/재시도 ID를 지우지 않는다. 새로고침 시 File을 유지할 수는 없으므로 재선택해야 한다.
- 학교가 다른 기존 탐구/작품 초안은 자동 변경하지 않는다. 빈 화면에만 링크 학교를 추천 선택한다. 교사의 링크 발급과 학생의 학교 변경은 기존 활동코드/학생 기록을 수정하지 않는다.
- 서버가 매번 만료·폐기·학교·JWT의 익명 UID·소유 작품 경로·승인 대기 상태·파일 크기/MIME/서명/SHA256을 검증한다. 학생이 보낸 ownerUid/만료 시각은 권한 근거로 사용하지 않는다.
- 기본 링크 30분, 최대 60분; 익명 UID별 서로 다른 작품 최대 3개, 링크 전체 기본 60개(서버 상한 300개), 권한 15분 이내. 이미지 3MiB/영상 15MiB/PDF 5MiB 및 링크별 더 작은 용량 제한을 모두 적용한다. 발급 시점부터의 서버 시계를 사용한다.
- 작품 키별 예약으로 같은 파일 재시도는 횟수를 다시 차감하지 않는다. 실패한 전송의 예약도 한도를 차지한다. 첫 파일과 다른 SHA256·크기를 같은 키로 재전송할 수 없다. 기존 일일/전체 용량 제한도 유지한다.
- 최종 저장 승인은 SQL 트랜잭션에서 초대 행을 잠그고 만료·폐기·UID·학교를 재검사한 뒤 ledger ready를 변경한다. 폐기가 먼저 확정된 전송은 거절하고 새 임시 객체만 정리한다. 기존 완료 파일은 실패한 재시도 때문에 삭제하지 않는다. 폐기는 이미 수신된 사본/완료 작품을 삭제하지 않는다.
- 초대 모드에서는 기존 인증코드/활동코드로 대체 인증하지 않는다. 상태 점검 기능도 초대 권한 없이 미완료 객체를 ready로 승격하지 않는다. 삭제 확인이 실패한 예약은 숨기지 않고 수동 점검 대상으로 남긴다.
- 익명 UID는 실명 또는 학생 1인 증명이 아니다. 새 브라우저 프로필을 만들면 새 UID가 생길 수 있다. 링크 전체 한도와 기존 서버 일일/용량 한도를 함께 적용한다. 링크를 수업 밖에 공유하지 않도록 안내해야 한다.

## 격리된 로컬 테스트 프로젝트

기존 Node 의존성(PGlite/Playwright)을 재사용하며 새 운영 의존성은 없다.

```sh
cd veteransgeo/security
npm ci --ignore-scripts
npm run mock:invites
```

출력된 **localhost 주소**의 `/teacher.html`에서 링크를 발급하고 학생 링크를 같은 PC에서 연다. 가상 교사/익명 UID, 메모리 Firebase/객체 저장소, 실제 PostgreSQL WASM 함수만 사용한다. 실제 Firebase/Supabase에 접속하지 않는다. 종료하면 가상 자료가 사라진다. 다른 기기에 공개하지 않는다. 외부 QR 생성 서비스는 사용하지 않는다.

```sh
# Linux 예: 설치된 브라우저 경로만 지정, 프록시/TLS 설정 변경 없음
VETERANSGEO_BROWSER=/usr/bin/chromium npm run test:media
VETERANSGEO_BROWSER=/usr/bin/chromium npm run test:browser
node --test production-readiness.test.mjs
```

관리형 브라우저의 `file://` 제한을 해제하거나 네트워크 통제를 우회하지 않는다. 호스팅된 테스트 프로젝트나 실제 학생 실습을 확인한 것으로 표시하지 않는다. 검증 결과는 PR 설명과 `UPLOAD-INVITES-RESULTS.md`에 구분한다.

## 별도 호스팅 테스트를 위한 준비 사항 — 이번에는 실행하지 않음

1. 운영과 다른 Firebase/Supabase 프로젝트 및 승인된 테스트 교사 UID/정확한 Origin을 확인한다. 기존 `rehearsalTargets`의 운영 차단을 유지한다. 실제 학생 자료는 사용하지 않는다.
2. 기존 private media SQL 다음에 `supabase/migrations/202610300001_upload_invites.sql`을 **테스트 프로젝트에만** 적용한다. 공개 RLS 정책을 추가하지 않는다.
3. 테스트 Edge 함수에만 `UPLOAD_AUTH_MODE=teacher-invite-link`를 명시하고, 테스트 클라이언트 설정도 `uploadAuthorization: "teacher-invite-link"`로 일치시킨다. 기본 공개 `media-config.js`는 disabled 상태다. 운영 entry는 변경하지 않았다. 설정이 불일치하면 거절하며 인증코드로 우회하지 않는다.
4. API 요청/응답 본문과 Authorization/X-Upload-Grant 헤더가 Edge·프록시·분석·오류 추적 로그에 저장되지 않도록 정책을 확인한다. **초대/권한 원문을 로그·스크린샷·GitHub·Notion·학생 기록에 붙이지 않는다.** 서비스 역할 키는 서버 전용으로 유지한다.
5. 모바일/학교 PC에서 교사 발급 → 학생 자동 연결 → 이미지·영상 전송 → 만료/폐기 → 글·파일 유지 → 새 링크 재연결 → 승인·공개·철회를 재검증한다. 토큰을 담는 외부 QR 생성기는 금지한다. QR이 필요하면 별도 검토된 기기 내 생성 방식을 사용한다.
