# 모션 선택·명세·검수

## 먼저 목적을 정한다

상태 피드백, 이동 맥락 유지, 시선 순서, 데이터 변화 설명, 학습 내용 표현 중 무엇을 위한 움직임인지 밝힌다. 움직임 자체가 목적이 아니라면 정지 상태로도 기능과 정보를 이해할 수 있어야 한다. 관리·장문·인쇄 화면에는 기본적으로 절제한다.

명세는 대상 / 트리거 / 움직임 / 시간 / 이징 + 이동량·스태거·반복·정지·움직임 줄이기 대안으로 작성한다. “부드럽게”만 적지 않는다.

실무 출발값: 눌림 약 150~200ms, 등장 약 300ms ease-out, 퇴장 약 200ms ease-in, 위치 변경 약 400ms ease-in-out, 목록 간격 약 60~80ms. 고정된 국제 의무 기준이 아니라 목적에 맞게 조절할 프로젝트 기본값이다.

## 구현 선택

CSS transition/keyframes → 필요한 경우 Web Animations API·SVG·canvas → 브라우저 지원이 맞으면 Scroll-driven/View Transitions → 복잡한 타임라인·컴포넌트 수명주기 등이 있을 때만 라이브러리 순으로 검토한다. 단순 효과에 React나 큰 프레임워크를 새로 도입하지 않는다.

GSAP는 타임라인, Motion은 React 전환, Anime.js는 트윈, Lenis는 스크롤, AOS는 등장, Lottie는 내보낸 애니메이션 재생, Rive는 상태 기반 인터랙션, Remotion은 영상 렌더의 필요가 있을 때 후보로 삼는다. After Effects의 Anchor Point·Easy Ease·Graph Editor·Trim Paths·Track Matte·Motion Blur·Parent/Null·Time Remapping·wiggle·loopOut 용어는 개념 대응에 활용한다. 요금·라이선스·현행 API는 도입 시 재확인한다.

## 접근성·성능 완료 기준

- prefers-reduced-motion에선 필수 정보가 즉시 최종 상태로 보이도록 한다. CSS뿐 아니라 JS/canvas 반복도 멈추거나 줄인다.
- 자동으로 오래 움직이는 콘텐츠에는 보이는 정지·재개 수단을 둔다. 호버 정지만으로 터치 사용자를 제외하지 않는다.
- 화면 전체 번쩍임·빠른 명도 변화는 피한다. 접근성 표준 준수 주장에는 실제 조건별 검증이 필요하다.
- transform·opacity를 우선하고 레이아웃 재계산·큰 블러·많은 입자 비용을 측정한다. 필요한 SVG·canvas 속성까지 무조건 금지하지 않는다.
- 화면 밖·백그라운드에서는 반복을 멈추고 정리 시 타이머·이벤트·애니메이션을 해제한다.
- 끈 상태, 미지원 브라우저, 느린 기기, 반복 클릭·취소에도 내용·포커스·조작이 유지되는지 확인한다.
- 단일 수치에 대한 과도한 카운트업·순위 이동으로 값이 왜곡되어 보이지 않게 하고 결과 수치는 정적으로도 제공한다.
