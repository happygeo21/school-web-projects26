# 검증·완료·GitHub 동기화

## 지속 승인 범위

사용자는 2026-10-14 “방금 작업한 것도 GitHub 작업 브랜치에 업로드”, “앞으로 작업 완료 후 GitHub 작업 브랜치에 항상 업로드”를 명시적으로 요청했다. 이 저장소의 승인된 작업 결과는 완료 시 별도 재확인 없이 작업 브랜치에 커밋·push한다.

이는 상시 백그라운드 동기화나 main 병합·운영 배포 승인이 아니다. 다른 저장소·무관한 로컬 변경까지 업로드할 권한으로 확대하지 않는다.

## 시작과 업로드

1. 현재 브랜치, Git 상태, origin, 관련 지침을 확인한다. 원격을 fetch해 같은 브랜치의 기존 작업을 확인한다.
2. 사용자의 미커밋 파일을 보존한다. 원격에 기존 작업이 있으면 덮어쓰지 않고 반영·통합한다. 원격 커밋을 없애는 force push는 하지 않는다.
3. 이번 요청의 수정·문서·필요한 테스트만 검토한다. 개인정보·토큰·임시 프로필·대용량 생성물은 포함하지 않는다.
4. 관련 검증을 실행한다. 통과하지 못한 작업을 완료로 표시하지 않는다. 환경상 못 한 검사는 명시한다.
5. 확인된 Git 작성자 정보로 로컬 커밋을 만든다. 다른 사람으로 가장하거나 인증정보를 추출하지 않는다. 로컬 인증이 없으면 지원되는 GitHub 연결 도구로 업로드할 수 있다.
6. 작업 브랜치로 업로드한다. 실패하면 안전한 대안을 시도하고 결과를 보존한다. 네트워크·로그인·권한 문제가 있으면 필요한 조치만 요청한다.
7. 로컬 HEAD와 원격 브랜치 SHA가 일치하는지 확인한다. 변경 파일 및 원격 링크를 보고한다.

## 필요한 검증만 수행

- HTML/JS: 문법, 영향받는 버튼·폼·상태, 실제 브라우저 오류.
- 디자인/UI: PC·모바일·태블릿, 긴 한글·확대·키보드, 정보 위계·색·포커스·빈 상태·실패·복구.
- 모션: 정지·움직임 줄이기·미지원 대안·반복/취소·성능.
- 인쇄: 예상 쪽수와 실제 A4 PDF, 수동 나눔, 붙여넣기, 저장·복원, 글자·여백·이미지, 페이지 경계.
- 데이터: 가상 자료·격리 환경, 권한·입력 검증·오류 처리. 운영 Firebase에 테스트 쓰기를 하지 않는다.
- 문서 지침만 수정한 경우: 링크·모순·범위·Git diff 검토로 충분하며 제품 테스트를 불필요하게 반복하지 않는다.

## 보고 형식

무엇을 바꿨는지 / 실제 확인한 결과 / 남은 한계 / 커밋과 GitHub 작업 브랜치 링크 / 운영 배포 여부를 구분해 짧게 보고한다. 복구가 필요하면 되돌릴 변경 또는 기준 커밋을 제시한다.

## 노트북에서 이어가기

처음에는 같은 저장소를 복제하고 작업 브랜치를 선택한다. 이후에는 작업 시작 전에 로컬 변경을 확인·보존한 뒤 원격 변경을 내려받는다. 끝나면 같은 방식으로 커밋·push한다. 동시에 같은 파일을 수정했으면 내용을 비교해 충돌을 해결한다.

AGENTS.md와 이 문서들은 저장소 파일이므로 같은 브랜치를 받으면 함께 전달된다. 설치한 앱·스킬·MCP 인증·브라우저 localStorage·이 채팅의 모든 기록이 GitHub로 전달되는 것은 아니다. 공개 GitHub Pages는 main 기준이므로 작업 브랜치 업로드만으로 공개 사이트가 갱신되지 않는다. Netlify 등 다른 배포 서비스의 브랜치 미리보기 설정은 실제 확인 없이 단정하지 않는다.
