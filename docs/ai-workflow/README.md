# 교사용 웹 프로젝트 작업 기준

사용자가 2026-10-14 제공한 도키피디아 다섯 자료와 K-Slide 선호를 이 저장소에 맞게 재구성한 실행 지침이다. 자료를 그대로 복제한 책이나 설치 완료 목록이 아니다.

## 작업별로 읽을 문서

| 상황 | 읽고 적용할 기준 |
|---|---|
| 방향이 모호함, 신규 앱, 큰 화면 변경 | [기획과 밑그림](planning.md) |
| HTML 제작, 디자인 개선 | [디자인과 UX](design.md), [UI 선택](ui.md) |
| 움직임, 전환, 게임, 차트 | [모션](motion.md) |
| 스킬·MCP·라이브러리·외부 도구 필요 | [도구 활용](tools.md) |
| 구현 완료, 다른 기기로 이어가기 | [검증과 GitHub 동기화](completion.md) |
| 자료 전체 범위와 용어 찾기 | [참고 자료 색인](reference-index.md) |

## 매번 적용할 흐름

1. 현재 파일·사용자 요구·Git 상태·관련 지침을 읽는다.
2. 원하는 결과와 완료 기준을 짧게 정리한다. 막힌 부분에는 추천안을 제시한다.
3. 디자인을 새로 정해야 하면 K-Slide 실제 확인 → 3안 비교 → 선택/위임 → 밑그림 및 화면 흐름 고정.
4. 필요한 부분만 구현하고 관련 상태·기기·접근성·오류 복구를 확인한다.
5. 변경과 검증 결과를 기록하고 작업 브랜치에 커밋·업로드한 뒤 원격 일치를 검증한다.
6. 운영 배포는 별도 승인 범위에서 수행한다. 코드 업로드만으로 노트북 파일이 저절로 갱신된다고 안내하지 않는다.

## 적용 우선순위

현재 사용자의 구체적인 지시와 상위 환경 제약을 먼저 따르고, 프로젝트 AGENTS.md, 확정된 하위 프로젝트 DESIGN.md, 이 문서의 일반 기준 순으로 적용한다. 일반 디자인 취향을 이유로 확정된 기능·톤을 뒤집지 않는다.

각 자료의 모든 장을 색인과 기준에 연결하되, 모든 UI·모션·제품을 매 화면에 넣지 않는다. 선택하지 않은 효과도 필요할 때 찾을 수 있게 용어 색인으로 보관한다. 기존 HTML을 자동으로 전면 개편하지 않는다.
