# UI 컴포넌트 선택과 검증

사용자가 “옆에서 나오는 메뉴”처럼 말해도 적절한 이름과 동작으로 번역하고 쉬운 말로 설명한다. 용어를 외우도록 요구하지 않는다. 모든 컴포넌트를 한 화면에 넣지 않는다.

## 프레임과 이동

- 헤더·푸터·앱 바를 구분한다. 소개 첫 화면의 히어로는 목적과 주 행동을 짧게 전달한다.
- 넓은 관리 화면은 사이드바 또는 목록/상세 분할을 검토하고 좁은 화면에서는 드로어 또는 목록→상세 이동으로 바꾼다.
- 스티키 헤더·하단 탭 바는 본문·포커스·마지막 목록 항목을 가리지 않게 한다.
- 햄버거는 앱 전체 메뉴, 케밥·미트볼은 항목 동작이다. 자주 쓰는 핵심 동작은 숨기지 않는다.
- 탭은 같은 화면의 내용 묶음, 세그먼티드는 같은 내용의 보기 방식, 위저드는 순서 있는 입력에 쓴다.
- 브레드크럼은 구조상의 위치, 목차는 긴 글 내부 이동에 쓴다. 현재 위치를 표시한다.
- 다시 찾기가 중요한 목록에는 페이지네이션, 계속 훑는 자료에는 더 보기/무한 스크롤을 고려한다. 무한 로딩의 종료·실패와 뒤로 가기 복원을 설계한다.
- 메가 메뉴는 큰 정보 구조에 한정하고 작은 학급 도구에는 과도하게 만들지 않는다.

## 겹쳐 뜨는 창과 상태

- 모달은 응답이 필요한 결정에 사용한다. 포커스 진입·가두기·복귀, 이름, Esc, 뒤 배경 조작 차단을 확인한다.
- 드로어는 주로 이동, 바텀 시트는 모바일 선택·상세, 팝오버는 맥락상 부가 정보에 쓴다. 모달/비모달 구분에 따라 키보드 동작을 정한다.
- 툴팁은 보조 설명만 담는다. 중요한 정보는 호버 없이도 읽을 수 있게 한다.
- 드롭다운 메뉴는 동작 실행, 셀렉트는 값 선택이다. 컨텍스트 메뉴·커맨드 팔레트의 기능에는 눈에 보이는 대체 진입점도 둔다.
- 라이트박스는 닫기·이전/다음·포커스 복귀를 제공하고 오버레이는 장식과 상호작용 차단 역할을 구분한다.
- 토스트/스낵바는 일시적 피드백, 배너는 지속 상태, 모달은 반드시 확인할 결정에 쓴다. 중요한 오류를 금방 사라지는 토스트에만 두지 않는다.
- 칩은 선택 조건, 배지는 상태·개수, 태그는 분류로 구분한다. 색만으로 의미를 전달하지 않는다.
- 진행률을 실제로 알면 진행 막대, 모르면 스피너, 구조를 알면 스켈레톤을 고려한다. 거짓 퍼센트를 표시하지 않는다.
- 빈 상태에는 이유와 다음 행동을, 실패에는 재시도를, 연결 끊김에는 복구 상태를 표시한다.
- 코치 마크는 필수 동작 몇 개로 제한하고 건너뛰기·다시 보기를 제공한다.

## 입력과 데이터

- 주요 버튼을 한 행동 묶음 안에서 분명히 하고 보조·파괴 동작과 구분한다. FAB는 콘텐츠를 가리지 않게 한다.
- 즉시 켜기/끄기는 토글, 복수 선택은 체크박스, 단일 선택은 라디오를 사용한다.
- 레이블은 placeholder로 대체하지 않는다. 필수/선택·단위·범위를 표시하고 오류를 해당 입력과 연결한다.
- 짧은 선택은 펼쳐 보이고, 긴 목록은 셀렉트·검색·자동완성을 검토한다. 검색 결과 없음과 키보드 선택을 구현한다.
- 근사값은 슬라이더, 작은 정수 범위는 스테퍼, 정확한 값은 숫자 입력을 고려한다. 최솟값·최댓값·잘못된 입력을 처리한다.
- 날짜·파일·range 등 네이티브 입력을 우선 검토한다. 직접 그린 컨트롤은 접근성 비용까지 책임진다.
- 드롭존은 클릭 업로드도 지원하고 종류·크기·제거·실패 상태를 표시한다. 실제 업로드 여부를 명확히 한다.
- 위저드는 이전 단계 값 보존과 전체 단계 수를 보여 준다. 별점은 각 점수 의미와 키보드 조작을 제공한다.
- 비교는 표, 훑기는 목록, 독립 항목은 카드에 담는다. 표의 정렬 방향·헤더·모바일 대응을 검증한다.
- 아코디언에는 선택적으로 읽는 내용을 넣고 필수 설명을 감추지 않는다.
- 대시보드 수치는 단위·기준 시점·비교 대상을 표시한다. 아바타는 필요한 경우만 쓰며 학생 사진을 기본 요구하지 않는다.
- 필터·정렬은 현재 적용 조건·초기화·결과 수를 보여 준다. 캐러셀에 필수 공지를 숨기지 않고 자동 재생에는 정지와 키보드 조작을 둔다.

## 게임·편집 도구

- HUD의 점수·시간·게이지는 주요 장면을 가리지 않게 하고 정확한 값이 중요하면 숫자를 함께 표시한다.
- 미니맵은 위치 파악, 편집 내비게이터는 확대된 작업 영역 이동에 사용한다.
- 대사 상자는 긴 글을 나누고 타자기 효과를 건너뛸 수 있게 한다. 인벤토리는 선택·사용·미보유 상태가 분명해야 한다.
- 수업용 게임의 일시정지는 화면뿐 아니라 게임 시간·입력도 멈춰야 한다. 모바일 조이스틱에는 적절한 PC 키보드 대안을 둔다.
- 교실 점수판·타이머는 먼 거리 가독성과 교사의 진행 제어를 우선한다.
- 툴바는 즉시 명령, 도구 팔레트는 계속 적용할 도구 선택, 인스펙터는 선택 대상 속성, 레이어 패널은 겹침 순서에 사용한다.
- 캔버스(작업 영역)와 HTML canvas 기술을 구분한다. 패널은 접을 수 있게 하고 줌은 작업 영역만 바꾸며 화면 맞춤을 제공한다.
- 드래그만 가능한 조작에는 키보드 또는 버튼 대안을 둔다. 타임라인은 시간 관계가 있을 때만 쓰고 순서만 있으면 목록으로 충분하다.
- 상태 표시줄은 보조 정보용이다. 꼭 봐야 할 오류를 그곳에만 표시하지 않는다.

## 공통 검수

Tab/Shift+Tab, Enter/Space, 필요한 방향키·Esc, 눈에 보이는 focus-visible, 터치, 확대, 긴 한글, 로딩·비활성·빈 상태·실패·성공을 확인한다. 역할에 맞는 실제 button/input/nav 등을 우선 사용한다. 컴포넌트 패턴이 복잡하면 WAI-ARIA APG·MDN·공식 디자인 시스템으로 동작을 재확인한다.
