# 디자인·UX 기준

## K-Slide에서 출발

HTML 신규 제작과 큰 디자인 개선은 https://k-slide.web.app/ 을 실제 확인한다. 목적에 맞는 실제 스타일 3안과 추천 1안을 먼저 보여 준다. 각 안은 스타일명, 색감, 한글 글꼴, 배치, 어울리는 수업 상황, 가독성·유지 부담의 차이를 설명한다.

Blue Professional / Playful / Editorial Forest / Block Frame / Soft Editorial은 사용자 선호 후보이다. 갤러리의 현재 이름·색·글꼴을 확인하고, 찾지 못하면 가상의 원본 설명을 만들지 않는다. 사용자가 선택을 위임하면 이유를 밝히고 추천안으로 진행한다.

## UX를 먼저 판단

- 정보 구조: 메뉴를 목적별로 묶고 이름과 계층을 먼저 정한다. 불필요한 단계와 기억해야 할 정보를 줄인다.
- 시각적 위계: 한 화면에서 가장 중요한 정보와 주 행동을 분명히 한다. 제목·본문·보조 정보의 크기·굵기·간격을 구분한다.
- 선택 부담: 선택지가 많으면 묶거나 단계적으로 공개한다. 필수 정보를 숨기지 않는다.
- 조작 단서: 눌리는 요소에는 명확한 표시를 주고 익숙한 탐색 관습을 따른다. 창의성은 주로 표현에 쓴다.
- 배치: 관련 레이블·입력·설명을 가깝게 두고 그룹은 여백으로 구분한다. 읽기 패턴은 참고이지 모든 화면을 F/Z 배치로 고정하는 법칙이 아니다.
- 피드백: 대기·성공·실패를 알리고 중복 제출을 막는다. 실패 시 입력을 보존하고 복구 방법을 제공한다.
- 첫 사용: 긴 소개보다 첫 성공을 돕는다. 다음 행동을 쉽게 찾게 한다.
- 신뢰: 가짜 마감·숨긴 취소·원하지 않는 기본 동의 등 사용자를 오도하는 화면을 만들지 않는다.
- 개선: 먼저 사용자가 어디서 막히는지 관찰한다. A/B 테스트는 비교 조건과 충분한 데이터가 있을 때만 선택한다. 근거 없는 표본 수·전환율을 보장하지 않는다.

## 표현 스타일 선택표

| 계열 | 사용할 이유 | 주의할 점 |
|---|---|---|
| 미니멀 | 문서·교사 업무, 정보 집중 | 요소만 빼서 빈약하게 만들지 않기 |
| 에디토리얼 | 지리 탐구·연구·이야기 | 한글 장문 가독성, 모바일 다단 해제 |
| 벤토 | 중요도가 다른 요약 정보 | 의미 없이 모든 내용을 카드로 만들지 않기 |
| 글래스모피즘 | 제한된 오버레이·깊이 표현 | 배경 위 대비·블러 비용 |
| 뉴모피즘 | 기기 제어 느낌의 작은 영역 | 경계·눌림 구별이 약하므로 일반 폼 기본값으로 쓰지 않기 |
| 브루탈리즘 | 행사·강한 개성 | 정보가 많은 교사 화면에는 절제 |
| 메시 그라디언트 | 제한된 표지 분위기 | 본문·강조 대비, 상투적 조합 반복 금지 |
| 다크·네온 | 게임·특정 데이터 도구 | 눈부심·색상만의 상태 구분 방지 |
| Y2K·레트로 | 학생 행사·특별 캠페인 | 학교 공문·관리 화면의 신뢰와 충돌 여부 |
| 3D·몰입형 | 공간 설명·전시 | 모바일 성능, 정적 대체, 조작 안내 |

표의 계열은 K-Slide의 실제 스타일명과 별개다. 갤러리 시안을 임의의 계열명으로 대체했다고 숨기지 않는다.

## 값으로 남기는 디자인 시스템

대상 폴더의 DESIGN.md에 주색·배경·강조·본문·보조·성공·경고·오류의 역할별 색값, 한글 폰트와 로딩·대체 경로, 제목/본문 크기와 줄간격, 간격 스케일, 너비·반응형 기준, 모서리·그림자, 기본·호버·포커스·눌림·비활성·로딩 상태를 적는다.

새 화면의 출발점으로 본문 16px 안팎, 간격 4·8px 계열을 검토하되 기존 인쇄 도구의 mm 단위 등 용도별 기준을 우선한다. 모든 하위 프로젝트를 같은 팔레트로 바꾸지 않는다. 색은 --surface, --ink, --accent 등 의미 중심 토큰으로 관리한다.

읽기 대비와 실제 한글 폰트 로딩을 확인한다. 일반 본문 대비 4.5:1, 큰 글자 및 필요한 비문자 요소 3:1을 검토 기준으로 사용하며 적용 예외·현행 규정이 문제되면 공식 접근성 문서를 확인한다. 터치 대상은 충분한 크기와 간격을 확보하고 44px 안팎을 사용성 목표로 고려한다. 이를 모든 WCAG 항목의 단일 최소값으로 잘못 부르지 않는다.

## 레퍼런스·에셋·검수

- 분위기 참고와 동작·배치 참고를 구분하고 자료마다 채택할 요소를 명시한다. 서로 충돌하는 시안을 무작정 많이 모으지 않는다.
- 새 에셋이 필요하면 고정할 특성과 바꿀 특성을 분리한다. 배경 이미지·영상 속에 읽어야 할 버튼·본문을 굽지 말고 실제 텍스트로 배치한다.
- 배경 영상·역재생 루프는 연속성이 자연스러운 경우만 쓰고 정지·정적 대체를 준비한다.
- 템플릿·폰트·이미지·아이콘의 라이선스를 확인한다. 참고 사이트를 그대로 복제하거나 원본으로 사칭하지 않는다.
- 기계적인 카드 중첩, 무분별한 알약 버튼·이모지·그라디언트 글자·발광 그림자, 단조로운 크기 위계를 점검한다. 특정 색 자체를 AI 생성의 확실한 증거라고 단정하지 않는다.
- PC·모바일·태블릿과 실제 긴 한글 내용으로 검증한다. 선택 시안과 구현이 달라진 곳 및 이유를 기록한다.
