# 보안 및 격리 검증

검토 대상: 기존 `happygeo/student.html`, `teacher.html`, `firebase-config.js`, `FIREBASE_SECURITY_GUIDE.md` 및 별도 2차시 화면. 운영 Firebase 읽기·쓰기·인증 요청은 이 작업에서 실행하지 않는다.

## 원본 분석

- 학생은 Firebase 익명 인증 UID를 학생 레코드 키로 사용한다. 교사는 Google 또는 이메일·비밀번호 Firebase 인증을 사용한다. 클라이언트 계정 필터만으로는 권한을 보장할 수 없고 실제 Realtime Database Rules가 최종 권한을 판정한다.
- 원본 DB 루트는 `energyMatchV10_3`이다. 기존 학생의 `answers`, `scores`, `interests`, `mix`는 이전 수업의 기록이므로 신규 수업 데이터로 덮어쓰면 안 된다.
- 원본 교사는 학급 전체를 구독하지만 안내된 규칙은 `meta`, `students`, `messages`별 읽기만 허용한다. RTDB 규칙은 필터가 아니므로 신규 화면은 각 노드를 개별 구독해야 한다.
- 원본 `innerHTML`의 번호·활동 제목·학급명·UID 일부에 escape가 없다. 신규 화면에서는 학생 입력을 `textContent`로 출력하거나 HTML escape한다.
- 원본 학생 권한 오류의 공개 규칙 적용 권유는 안전한 운영 안내가 아니다. 신규 화면에서는 관리자에게 기존 제한 규칙을 확인하도록 안내한다.
- Firebase 웹 설정은 공개 클라이언트 설정이며 서버 권한을 부여하지 않는다. 개인 교사 이메일이나 인증 토큰을 추가 공개하지 않는다.

## 검증 경계

`scripts/happygeo-firebase-fixture.cjs`는 테스트 전용 메모리 SDK이며 운영에 포함하지 않는다. 가상 학급 `TEST26`과 가상 학생만 취급하고 다른 경로를 거부한다. 본인 레코드 저장/조회와 다른 학생·교사 전용 경로 거부를 검증하기 위한 **클라이언트 계약 대역**이다.

로컬 데모의 저장·재조회는 localStorage 기능 검증이다. SDK 대역 테스트의 거부는 대역 정책에 따른 것으로 실제 배포된 Rules의 안전성을 입증하지 않는다. 실제 Rules, 승인 교사 계정, 운영 학급의 저장/조회와 다중 기기 동기화는 운영 접근 승인이 없으므로 미확인이다.

Firebase CLI와 `@firebase/rules-unit-testing`는 현재 번들에 없다. Node 및 Playwright와 설치된 Edge 브라우저를 사용한다. 실제 규칙 에뮬레이터 검증은 운영 규칙을 비식별 형태로 제공받고 도구를 설치한 격리 환경에서 별도로 수행해야 한다. 운영 규칙 배포는 이번 변경에 포함하지 않는다.

## 실행 결과

- `node --test scripts/happygeo-fixture.test.cjs`: 4/4 통과. 가상 학생 본인 저장·재조회, 이전 필드 보존, 다른 학생·학급 전체 읽기 및 교사 메타 쓰기 거부, 가상 교사 조회, 권한 오류와 격리 경로 차단.
- `node scripts/happygeo-v2.browser-test.cjs`: 실제 Chrome 브라우저에서 5/5 통과. 데모 참여→저장→페이지 새로고침→재입장 복원→교사조회, Firebase SDK 대역 신규 노드만 쓰기·기존 4개 필드 보존, 권한 거부 오류 전파, 통합 학생·교사 화면 클릭, 실제 학생 UI의 저장 실패 처리 검증.
- `node --test scripts/public-boundary.test.mjs scripts/happygeo-fixture.test.cjs`: 저장소의 기존 공개 경계 회귀검사를 포함하여 5/5 통과.
- 브라우저 테스트는 모든 로컬 파일을 Playwright `route.fulfill`로 공급하며 외부 요청을 차단한다. 데모 저장소 테스트의 외부 요청은 0건이다. 이 환경은 로컬 서버에 대한 실제 소켓 접속이 제한되어 있고 Edge 프로필 실행에도 오류가 있어 설치된 Chrome을 사용했다.

통합 화면은 가상 교사 학급 생성, 가상 학생 참여, 프로필 모달, 관심 선택, 서로 다른 3명 영입, 연료 3종 선택과 지도 경로 Enter 키 선택, 선택 경로 확대의 viewBox 변경·세계 전체 보기 원복, 지도 메모·제안서·돌발 응답 저장, 10문항 정답 선택, 새로고침 후 복원, 교사 집계(1명·10.0/10·완주 100%)와 상세 보기를 확인했다. HTML 태그를 포함한 학생 별명은 텍스트로 출력되며 이미지 요소가 생성되지 않았다. 1440px PC 및 390px 모바일에서 페이지 가로 넘침이 없고 JavaScript pageerror가 0건이었다. 앱은 로컬 시스템 폰트를 사용한다.

저장 실패 UI 테스트에서는 정상 입장·최초 저장 뒤 SDK 대역의 쓰기를 거부하도록 전환했다. 실제 학생 화면에서 메모를 작성하고 저장하면 `저장 실패` 상태와 `PERMISSION_DENIED` 안내가 나타나고 입력 내용이 유지된다. 이전 저장값은 바뀌지 않으며 데모 localStorage 키도 생성되지 않아 로컬 성공 폴백이 없음을 확인했다.

`docs/happygeo/previews/`에 PC·모바일 프로필, 지도, 교사 화면과 학생 첫 화면·팀·돌발 미션을 캡처했다. `world-mobile-zoom.png`는 선택 경로 확대 상태이며 육안으로 국가명과 방향을 확인했다. Playwright 브라우저 테스트를 다시 실행하면 현재 화면으로 덮어쓴다. 미리보기는 가상 데이터만 포함한다.
